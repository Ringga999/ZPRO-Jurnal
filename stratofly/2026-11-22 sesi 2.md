\## 5. Masalah, Blocker, \& Pelajaran



\### 5.1 First-run dry-run = 0 (UX, bukan bug)

\- Placeholder textarea abu-abu ≠ data; dry-run atas input kosong = 0 baris; export MD kosong.

\- \*\*Pelajaran:\*\* fitur analisis perlu \*\*sample loader\*\* agar first-run hidup \& demo-able. Utang Inc-1b.



\### 5.2 Panel fitur di dashboard = tidak scalable (DITOLAK penulis, benar)

\- Dengan \~100 role, menumpuk panel di dashboard merusak IA.

\- \*\*Resolusi:\*\* arsitektur workspace role-scoped; dashboard hanya ringkasan + kartu; fitur hidup di `/work`.

\- \*\*Pelajaran:\*\* skala masa depan harus jadi constraint desain sejak awal, bukan refactor belakangan.



\### 5.3 Permintaan snippet JS yang tidak diperlukan (koreksi proses)

\- Asisten meminta paste blok JS render kartu untuk anchor W2; ternyata \*\*runtime delegation\*\* (cari grid via heading "Live Crew") cukup dan lebih aman.

\- \*\*Pelajaran:\*\* sebelum meminta artefak dari penulis, cek apakah bisa ditemukan sendiri saat runtime. Hemat beban penulis = hormat.



\### 5.4 Kebingungan penulis soal Ctrl+F (dijelaskan)

\- Penulis menyangka harus paste JS; yang dibutuhkan asisten hanyalah konfirmasi anchor heading (baris 124). Klarifikasi menutup kebingungan.

\- \*\*Pelajaran:\*\* instruksi ke penulis harus menyebut TUJUANnya ("cukup konfirmasi baris heading"), bukan prosedur yang terkesan besar.



\### 5.5 Persistensi settings masih localStorage (sengaja, bertahap)

\- W4 menyimpan per-agent di localStorage agar nol risiko anchor \& nol perubahan settings.json (allowlist menolak key asing = pola M26).

\- \*\*Konsekuensi jujur:\*\* settings belum server-side, belum ikut persona agent sesungguhnya; itu W5.



\### 5.6 Drafters bergantung key NVIDIA (perilaku jujur)

\- Tanpa key, /api/ask gagal dan kotak draft menampilkan error — bukan draft palsu. Ini integritas, bukan cacat.
